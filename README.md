# SpacePC firmware

This repository contains browser-installable firmware projects for SpacePC
hardware and generic ESP32 development boards.

## Project layout

```text
projects/
  dummy-test/
  ds18b20-mqtt/
  orb/
  sleep-buddy/
  spacepc-homeassistant-display/
  spacepc-weather-display/
scripts/
  prepare-release.mjs
lib/
  SpacePCPortal/
```

`dummy-test` verifies the build and release pipeline without controlling
hardware. `ds18b20-mqtt` is a configurable temperature sensor with a local web
interface, native Home Assistant discovery and optional MQTT publishing.
`orb` is an animated live aircraft, satellite and ISS tracker for the
Waveshare ESP32-P4-WIFI6-Touch-LCD-4.3.
`sleep-buddy` performs local snoring detection, night summaries and optional
microSD audio recording on the Waveshare ESP32-P4-WIFI6-Touch-LCD-4.3.
`spacepc-homeassistant-display` is a Home Assistant-managed e-paper dashboard.
`spacepc-weather-display` is an independent OpenWeatherMap weather dashboard
for the Good Display ESP32-L, DESPI-C02 and GDEY075Z08.

Functional projects should use `lib/SpacePCPortal` for the shared Wi-Fi setup,
web interface, SpacePC API, mDNS service, optional MQTT connection and
transmission interval. Projects register only their hardware-specific fields
and entities so that setup and Home Assistant behavior remain consistent
across firmware.

## Home Assistant architecture

SpacePC devices expose a local, versioned API and advertise
`_spacepc._tcp.local.`. The
[`SpacePC Home Assistant integration`](https://github.com/spacepc-de/home-assistant-spacepc)
uses that interface without requiring an MQTT broker.

MQTT remains an optional output for other local systems. Enabling Home
Assistant MQTT Discovery is a separate compatibility path and is not required
by the native integration.

## Local build

Install PlatformIO Core and build one project:

```sh
python3 -m pip install platformio==6.1.18
cd projects/dummy-test
pio run
```

Use `projects/ds18b20-mqtt` to build the sensor firmware for classic ESP32,
ESP32-S2, ESP32-S3 and ESP32-C3 development targets.
The two display projects target the confirmed Good Display ESP32-L, DESPI-C02
and GDEY075Z08 hardware combination.

## Continuous integration

Every push and pull request compiles all project targets. Toolchain, platform
and third-party library versions are pinned for reproducible builds.

## Firmware releases

Test release tags use `dummy-test-v<semantic-version>`, for example:

```sh
git tag dummy-test-v0.1.0
git push origin dummy-test-v0.1.0
```

Functional sensor releases use `ds18b20-mqtt-v<semantic-version>`.
Display releases use `spacepc-homeassistant-display-v<semantic-version>` and
`spacepc-weather-display-v<semantic-version>`.

The release workflow:

1. compiles every target supported by the tagged project;
2. reads the flash offsets generated by the build;
3. creates an ESP Web Tools manifest;
4. calculates SHA-256 checksums;
5. publishes immutable GitHub Release assets.

Never replace assets belonging to an existing version. Test every release on
the exact compatible board revision before marking it stable on spacepc.dev.

## Safety

Each functional project documents its own supported voltage, wiring and known
limitations. Generic board targets verify compilation only; they do not prove
that every similarly named third-party board has identical pins or flash
layout.
